결제 시스템 설계

성과

  • 한번에·나눠서·나중에 직접 결제 등 결제 방식별로 나뉘어 있던 프로세스를 하나의 결제 흐름과 데이터 모델로 통합

  • Redisson 분산 락으로 여러 사용자가 동시에 결제를 시도해도 결제자 중복과 중복 주문 없이 처리

내용

  • 결제 데이터 설계

  • 주문 단위 결제 정보(payments)와 PG 거래 단위(payment_tx)를 1:N 테이블로 분리하고 거래별 결제 대상(전체 주문·금액·메뉴)을 기록하여, 한번에 결제·N분의 1 결제·메뉴별 결제를 하나의 데이터 모델로 처리

  • 환불·취소는 원거래를 수정하는 대신 원거래를 참조하는 별도 PG 거래 단위(payment_tx)로 기록해, 부분 환불과 거래 이력을 그대로 보존

  • 결제 프로세스 재설계

  • 한번에 결제: 장바구니를 공유하는 사용자 중 먼저 결제를 시작한 사용자만 결제자로 지정(Redisson 분산 락)하고, 다른 사용자에게는 WebSocket으로 결제 진행 중임을 알려 중복 결제 차단

  • 결제자가 이탈하면 일정 시간 후 결제 잠금을 자동 해제하여 다른 사용자가 이어서 결제

  • 나눠서 결제: 각자 N분의 1 금액 또는 원하는 메뉴만 결제하되, 결제 전 이탈로 빈 주문이 남지 않도록 주문을 먼저 만들지 않고 첫 결제가 성공할 때 생성하고, 이후 결제는 기존 주문에 추가 (동시 결제는 Redisson 분산 락으로 제어)

  • 키오스크 결제: 한 기기를 여러 고객이 차례로 쓰는 특성에 맞춰 장바구니 키를 기기 단위가 아닌 접속 세션 단위로 분리하고, 주문 이후 비동기로 오는 수락·결제 결과도 주문 ID→세션 매핑으로 해당 고객 화면에만 반영하여 고객 간 장바구니·결제 상태가 섞이지 않도록 구성

  • PG 서버의 결제 완료 콜백(S2S)과 클라이언트 리다이렉트를 함께 처리하여 결제 후 사용자가 이탈해도 주문이 누락 없이 확정되도록 하고, PG 거래번호 기준 멱등 처리로 두 경로에서 같은 결제가 중복 요청되어도 주문은 한 번만 확정

  • PG 연동

  • 토스페이먼츠·페이허브·나이스페이먼츠 PG 연동 및 QR·링크를 통한 나눠서 결제 공유 기능 개발

POS·외부 플랫폼 연동

성과

  • 저녁 피크에 서버가 자동 확장돼도 매장 POS 주문 전송이 끊기지 않도록 다중 인스턴스 구조로 전환

  • POS가 주문을 실제로 수신한 뒤에만 접수 처리하도록 바꿔, 테이블 점유 등으로 전송이 지연될 때 주문이 잘못 접수된 것으로 표시되던 문제 해결

  • 네이버 플레이스와 주문 데이터를 연동하여 고객이 영수증 없이 바로 네이버 리뷰를 남길 수 있는 흐름 제공

내용

  • POS 연동

  • 이지포스 신규 연동 — 마스터 데이터는 KICC 클라우드에 직접 요청(XML)하고, 주문은 POS 에이전트(WebSocket)를 거쳐 매장 로컬 POS로 전송하는 구조로 설계·개발

  • 사장님이 POS에서 테이블을 열어 둔 사이 들어온 주문을 이지포스가 "테이블 사용 중"으로 거절하던 문제를, 이 응답을 실패로 보고 바로 거절하는 대신 일시적 상태로 판단해 백그라운드에서 10초 간격·최대 5분간 재전송하도록 해결

  • 모든 POS 연동 매장이 카테고리·상품/옵션·상품 설명·이미지 중 원하는 항목만 POS와 동기화할 수 있도록 항목별 On/Off 기능 제공

  • POS 다중 인스턴스 지원

  • 저녁 피크에 CPU 증가로 서버가 자동 확장되며, POS 에이전트 소켓이 연결되지 않은 서버로 들어온 요청이 POS에 전달되지 않는 장애(약 95분) 발생

  • 주문이 POS에 들어가지 않는다는 사장님 문의로 장애를 인지하고, 우선 서버 스펙을 올려 인스턴스를 1대로 고정해 서비스를 복구한 뒤 다중 인스턴스 구조 전환 진행

  • POS 에이전트 WebSocket 세션이 연결된 인스턴스에만 존재하는 한계를, Redis에 세션 보유 인스턴스를 기록하고 Pub/Sub으로 해당 인스턴스에 명령을 라우팅한 뒤 요청 ID 기반 Request-Reply로 응답을 돌려받는 구조로 해결하여, 어느 인스턴스로 들어온 요청이든 POS에 전달되도록 전환

  • 서버 재시작 시 전 매장 POS 에이전트가 동시에 재접속해 DB 커넥션 풀이 포화되지 않도록, 에이전트 재연결에 지수 백오프·Full Jitter를 적용해 매장별 재접속 시점을 무작위로 분산

  • 네이버 플레이스 연동

  • 결제 완료 화면에서 영수증 없이 바로 네이버 리뷰를 남길 수 있는 기능을 신규·레거시 서버 모두에 개발

  • 선불(주문 시 결제)과 후불(식사 후 테이블 정리 시 결제)은 결제가 확정되는 시점이 달라, 선불은 결제 완료 즉시 주문 건별로, 후불은 테이블 정리 시점에 같은 테이블 주문을 묶어 그룹 단위로 네이버에 전송하도록 결제 유형별 전송 로직 분리
